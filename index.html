Inicio

¿Cómo funciona este tutorial?

En lugar de ver cada modificador por separado, aquí vamos a construir una sola clase desde cero: la clase Estudiante, que guarda el nombre y la nota de un alumno. En cada paso le hacemos un cambio, vemos qué pasa al ejecutar el programa y entendemos por qué.

Cada paso incluye el código de ese momento, la salida en consola (o el error que daría), la explicación línea por línea de lo importante y un resumen de lo que aprendiste.

Antes de empezar: ¿qué es una clase? Una clase es un molde para crear objetos. La clase Estudiante describe qué datos tiene un estudiante (nombre, nota) y qué puede hacer. Con ese molde podemos crear muchos estudiantes, como Ana, Luis o María, y cada uno es un objeto.

El mapa: ¿quién puede entrar?

Los modificadores de acceso funcionan como círculos, uno dentro de otro. Mientras más adentro, menos partes del programa pueden ver el dato:

public Todo el programa, incluso otros proyectos
internal Todas las clases del mismo proyecto
protected La clase y sus clases hijas
private Solo la propia clase

Vamos a recorrer este mapa paso a paso.

Empezar: Paso 1 →
Paso 1

Creamos la clase sin ninguna protección

Empezamos con lo más simple: una clase con dos datos y todo abierto.

Paso1.cs
using System;

public class Estudiante
{
    public string nombre;
    public double nota;
}

class Programa
{
    static void Main()
    {
        Estudiante ana = new Estudiante();
        ana.nombre = "Ana";
        ana.nota = -50;   // ¿Una nota negativa?
        Console.WriteLine(ana.nombre + " sacó " + ana.nota + " puntos");
    }
}
>_ Salida en consola
Ana sacó -50 puntos

Línea por línea

  1. public class Estudiante crea el molde llamado Estudiante.
  2. public string nombre; y public double nota; son los datos (atributos) que tendrá cada estudiante.
  3. new Estudiante() crea un objeto: un estudiante real hecho con el molde.
  4. ana.nota = -50; le asigna una nota… y el programa la acepta sin quejarse.
El problema En nuestro sistema las notas van del 0 al 20, pero el programa aceptó un -50. Como nota está abierta a todo el mundo, cualquier parte del código puede ponerle cualquier valor. En los siguientes pasos lo vamos a arreglar.
Siguiente: public →
Paso 2

Entendiendo public

En el paso 1 todo era public. Esta palabra significa: "cualquier parte del programa puede ver y usar esto", incluso desde otros proyectos.

¿Para qué sirve? Para lo que la clase quiere ofrecer a los demás, como sus acciones principales. Por ejemplo, un método para saludar sí debe ser público, porque queremos que se use:

Paso2.cs
public class Estudiante
{
    public string nombre;

    public void Saludar()
    {
        Console.WriteLine("Hola, soy " + nombre);
    }
}

// En el Main:
Estudiante luis = new Estudiante();
luis.nombre = "Luis";   // Permitido: nombre es public
luis.Saludar();         // Permitido: Saludar es public
>_ Salida en consola
Hola, soy Luis
Lo que aprendiste public es como la puerta principal de una tienda: todo el mundo puede entrar. Está bien para los métodos que la clase ofrece, pero no para datos delicados como la nota, porque cualquiera la puede dañar.
Siguiente: private →
Paso 3

Protegemos la nota con private

Cambiamos una sola palabra: nota pasa de public a private.

Paso3.cs
public class Estudiante
{
    public string nombre;
    private double nota;   // Ahora es privada
}

// En el Main:
Estudiante ana = new Estudiante();
ana.nombre = "Ana";
ana.nota = -50;   // Intentamos lo mismo que antes
✕ Error al compilar
error CS0122: 'Estudiante.nota' no es accesible debido a su nivel de protección

¿Qué pasó?

private significa: "solo la propia clase puede usar esto". Como el Main está fuera de la clase Estudiante, el compilador no le deja tocar la nota. Ya nadie puede poner un -50 desde afuera.

Dato importante: si no le escribes ningún modificador a un atributo o método, C# lo toma como private automáticamente.

Pero ahora hay un nuevo problema La nota quedó tan protegida que nadie puede leerla ni asignarle una nota válida, como un 18. Necesitamos una forma controlada de entrar. Eso es el encapsulamiento.
Siguiente: encapsulamiento →
Paso 4

Encapsulamiento: una puerta con vigilante

El encapsulamiento consiste en dejar el dato private y crear una propiedad pública que decida qué valores se aceptan. La propiedad tiene dos partes:

  • get: se ejecuta cuando alguien quiere leer el valor.
  • set: se ejecuta cuando alguien quiere cambiar el valor. Lo que intentan guardar llega en la palabra value.
Paso4.cs
using System;

public class Estudiante
{
    public string nombre;
    private double nota;          // El dato sigue escondido

    public double Nota            // La "puerta" pública
    {
        get { return nota; }
        set
        {
            if (value >= 0 && value <= 20)
                nota = value;
            else
                Console.WriteLine("Error: la nota debe estar entre 0 y 20.");
        }
    }
}

class Programa
{
    static void Main()
    {
        Estudiante ana = new Estudiante();
        ana.nombre = "Ana";
        ana.Nota = -50;   // El vigilante lo rechaza
        ana.Nota = 18;    // Este sí pasa
        Console.WriteLine(ana.nombre + " sacó " + ana.Nota + " puntos");
    }
}
>_ Salida en consola
Error: la nota debe estar entre 0 y 20.
Ana sacó 18 puntos

Línea por línea

  1. private double nota; el dato real sigue protegido.
  2. public double Nota es la propiedad; se escribe con mayúscula para diferenciarla del atributo.
  3. ana.Nota = -50; entra al set; el if ve que -50 no está entre 0 y 20 y muestra el error. La nota no cambia.
  4. ana.Nota = 18; el if lo acepta y guarda 18 en nota.
  5. ana.Nota dentro del WriteLine entra al get y devuelve 18.
Lo que aprendiste Encapsular es esconder los datos con private y dejar que se usen solo a través de propiedades o métodos públicos que los controlan. Así la clase se protege sola de valores incorrectos. ¡Ya resolvimos el problema del paso 1!
Atajo: propiedades automáticas Si un dato no necesita validación, C# 5 permite escribir la propiedad en una sola línea: public string Nombre { get; set; }. C# crea el atributo privado por dentro.

Paso 5

Una clase hija y protected

Ahora queremos una clase EstudianteBecado que herede de Estudiante: que tenga todo lo de un estudiante y además sepa si mantiene la beca, que se pierde con menos de 16 puntos.

Para eso la clase hija necesita leer la nota. Veamos qué pasa si la nota sigue siendo private:

Paso5_intento.cs
public class EstudianteBecado : Estudiante   // ":" significa "hereda de"
{
    public string EstadoBeca()
    {
        if (nota >= 16)   // nota sigue siendo private en Estudiante
            return "Mantiene la beca";
        else
            return "Pierde la beca";
    }
}
✕ Error al compilar
error CS0122: 'Estudiante.nota' no es accesible debido a su nivel de protección

Aunque sea su hija, private no la deja pasar. La solución es protected, que significa: "solo la propia clase y sus clases hijas".

Paso5.cs
public class Estudiante
{
    public string nombre;
    protected double nota;   // Cambiamos private por protected
    // ... la propiedad Nota queda igual ...
}

public class EstudianteBecado : Estudiante
{
    public string EstadoBeca()
    {
        if (nota >= 16)      // Ahora sí: es su clase hija
            return "Mantiene la beca";
        else
            return "Pierde la beca";
    }
}

// En el Main:
EstudianteBecado luis = new EstudianteBecado();
luis.Nota = 15;
Console.WriteLine(luis.EstadoBeca());
// luis.nota = 20;   ERROR: desde el Main sigue sin poder tocarse
>_ Salida en consola
Pierde la beca
Lo que aprendiste protected es como un secreto de familia: lo saben los padres y los hijos, pero nadie de afuera. Se usa cuando una clase hija necesita trabajar con datos de la clase padre sin dejarlos abiertos a todo el programa.
Siguiente: internal →
Paso 6

Un extra: internal

Hay un modificador más que conviene conocer. internal significa: "cualquier clase de este mismo proyecto puede usarlo, pero otros proyectos no". Si una clase no tiene modificador, C# la toma como internal.

Paso6.cs
internal class RegistroDeNotas
{
    internal void Guardar(Estudiante e)
    {
        Console.WriteLine("Guardando la nota de " + e.nombre);
    }
}
// Cualquier clase de nuestro proyecto puede usar RegistroDeNotas.
// Si otro proyecto la intenta usar, dará error.

También existe protected internal, que suma las dos cosas: se puede usar en todo el proyecto y en clases hijas de otros proyectos.

Final

El programa completo

Así queda la clase después de todos los pasos. Cada dato tiene el modificador que le corresponde según quién debe usarlo:

Programa.cs
using System;

public class Estudiante
{
    public string Nombre { get; set; }   // public: todos pueden verlo
    protected double nota;               // protected: la clase y sus hijas
    private string cedula;               // private: solo esta clase

    public Estudiante(string nombre, string cedula)
    {
        Nombre = nombre;
        this.cedula = cedula;
    }

    public double Nota                   // Encapsulamiento de nota
    {
        get { return nota; }
        set
        {
            if (value >= 0 && value <= 20)
                nota = value;
            else
                Console.WriteLine("Error: la nota debe estar entre 0 y 20.");
        }
    }

    public string CedulaOculta()         // Muestra la cédula sin revelarla completa
    {
        return "V-*****" + cedula.Substring(cedula.Length - 3);
    }
}

public class EstudianteBecado : Estudiante
{
    public EstudianteBecado(string nombre, string cedula) : base(nombre, cedula) { }

    public string EstadoBeca()
    {
        if (nota >= 16)
            return "Mantiene la beca";
        else
            return "Pierde la beca";
    }
}

class Programa
{
    static void Main()
    {
        EstudianteBecado ana = new EstudianteBecado("Ana", "28123456");
        ana.Nota = 25;
        ana.Nota = 18;

        Console.WriteLine("Estudiante: " + ana.Nombre);
        Console.WriteLine("Cédula: " + ana.CedulaOculta());
        Console.WriteLine("Nota: " + ana.Nota);
        Console.WriteLine(ana.EstadoBeca());

        // ana.cedula = "123";   ERROR: es private
        // ana.nota = 20;        ERROR: es protected
    }
}
>_ Salida en consola
Error: la nota debe estar entre 0 y 20.
Estudiante: Ana
Cédula: V-*****456
Nota: 18
Mantiene la beca

Práctica

Pon a prueba lo que aprendiste

Piensa la respuesta primero y después toca cada pregunta para ver si acertaste.

1. ¿Qué pasa si escribes ana.cedula = "123"; en el Main?
Da error al compilar (CS0122), porque cedula es private y solo se puede usar dentro de la clase Estudiante.
2. ¿Por qué EstudianteBecado puede leer nota y el Main no?
Porque nota es protected: la pueden usar la clase Estudiante y sus clases hijas. EstudianteBecado es hija; el Main no.
3. Si ejecutas ana.Nota = 21;, ¿qué se muestra y cuánto vale la nota después?
Se muestra "Error: la nota debe estar entre 0 y 20." y la nota se queda con el valor que tenía antes, porque el set no la guardó.
4. Tienes una clase CuentaBancaria con un atributo saldo. ¿Qué modificador le pondrías y cómo dejarías depositar dinero?
saldo debe ser private, y se agrega un método público que valide el monto:
CuentaBancaria.cs
private double saldo;

public void Depositar(double monto)
{
    if (monto > 0)
        saldo = saldo + monto;
}
5. ¿Qué modificador tiene un atributo si no le escribes ninguno?
private. En cambio, una clase sin modificador es internal.
Cierre

Conclusión

Construyendo la clase Estudiante paso a paso vimos que los modificadores de acceso no son solo palabras: cada uno resuelve un problema. public abre lo que la clase ofrece, private protege los datos, protected los comparte con las clases hijas e internal los limita al proyecto. El encapsulamiento une todo esto: esconde los datos y controla cómo se usan, para que el programa no acepte valores incorrectos como una nota de -50.
